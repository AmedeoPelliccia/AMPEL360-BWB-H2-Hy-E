## Change Log Format

Each change entry includes:

| Field | Description |
|-------|-------------|
| Change ID | Unique identifier (CHG-57-03-NNN) |
| Date | Date of change |
| Requirement ID | Affected requirement(s) |
| Change Type | Add, Modify, Delete |
| Description | Summary of change |
| Rationale | Justification for change |
| Impact | Downstream impact assessment |
| Approved By | Authority approving change |

## Change Request Process

### Process Steps

1. **Initiate**: Submit change request with rationale
2. **Assess**: Impact analysis (safety, design, V&V, schedule)
3. **Review**: Requirements Board review
4. **Approve**: Authority approval
5. **Implement**: Update requirement documentation
6. **Trace**: Update traceability matrices
7. **Notify**: Inform affected stakeholders

### Change Classification

| Classification | Description | Approval Authority |
|----------------|-------------|-------------------|
| Editorial | Typos, formatting | Requirements Lead |
| Minor | Clarification, no impact | Requirements Board |
| Major | Technical change, downstream impact | Project Authority |
| Safety | Safety-related change | Safety Board |

---

## Impact Assessment Template

For each significant change, document:

| Impact Area | Assessment | Affected Items |
|-------------|------------|----------------|
| Safety | Impact on safety objectives | Hazards, mitigations |
| Design | Impact on design baseline | Drawings, models |
| V&V | Impact on verification | Test plans, analyses |
| Schedule | Impact on milestones | Timeline |
| Cost | Impact on budget | Resources |
